A working publication for one idea at a time

The template, not the topic

One layout that holds an argument, a number, a piece of code, and a caveat — without being redesigned each time.
By the editors·2,100 words·August 2026

A publication template earns its keep the second time it is used. The first article is easy: any layout can carry one headline and a thousand words. The trouble starts when the next piece arrives with a table, or three code blocks, or a single number that has to land harder than the sentence around it.

So the elements come first, and the article second. Each one has a fixed job and a fixed treatment, and nothing is invented at writing time.

Margin note
Set the measure before the type size. A justified column wants 62–72 characters; below that, the rag gets ugly fast.

What each element is for

The drop cap marks the true beginning, which matters when a page carries a masthead, a deck, and a byline before the first sentence. It appears once per article and never after a subhead.

Code is set flush and unjustified, on a tinted band, so the eye reads it as an artifact rather than prose. Inline code such as --dry-run stays in the sentence.1

$ padj build --issue 01 --format both → publication.pdf (8 pages, letter) → publication.html (responsive)

Numbers get a chart only when the shape of the comparison is the point. Three bars, one label per bar, no gridlines, no legend — the caption carries the claim, and the axis carries nothing.

Everything else is prose, which is the format's default state and the one it should be best at.

A template is a set of decisions you agree not to make again.
1 Monospace inline runs stay at 0.85em of the body size so they sit on the same baseline grid.
