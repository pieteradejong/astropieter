# Changelog

All notable changes to this site. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
The site is unversioned (every push to `main` deploys), so entries are grouped by the session
that shipped them; `[Unreleased]` is what is on `main` but not yet deployed or not yet confirmed
live.

## [Unreleased]

### Added
- The `Command & Conquer in the browser` project page (`cnc-web`), synced from that repo's `portfolio.md`, with a live demo at https://cnc-web-padj.vercel.app (DECISIONS #20).
- Production waits for CI. A push to `main` goes live only after `tests`, `security / gitleaks` and `security / gate` pass (Vercel Deployment Checks). A red check keeps the previous build live (DECISIONS #26).
- `test.sh` § Prose integrity: Pieter's prose is pinned by hash. These pages are covered: Home, About, Contact, Reading, every published post, and the footer. Each block of visible text is hashed into `tests/prose.sha256`, so markup and styling can change freely while a reworded sentence fails, and the failure shows the old and new snippets. `--live` runs the same check against production. Pieter signs off on a change with `./test.sh --bless-prose` (DECISIONS #25).
- Each project page ends with a note saying whether its description was generated by AI, with a sparkle icon when it was. `aiGenerated` is a required project field, and all five current descriptions are AI-written (DECISIONS #23).
- The README has a table of the processors that receive visitor data (DECISIONS #22).
- `test.sh` checks more:
  - every internal link and `#fragment` in the build resolves
  - the settled biography facts (§ Biography consistency)
  - the contact form's privacy and spam guards
  - the AI authorship note on every project page
  - no third-party scripts
  - with `--live`, the /press and /software redirects and the honeypot.
- `scripts/sync-projects.sh`: project pages come from each public repo's `portfolio.md`. Its `public: true|false` flag decides whether the project is listed on `/projects`; hosting is separate. Generated pages carry `syncedFrom`, and hand-written pages are never touched. `docs/PORTFOLIO.md` § Publishing a project describes the new flow (DECISIONS #20).

### Fixed
- The contact form has a hidden `botcheck` honeypot, so Web3Forms drops bot submissions (DECISIONS #22).
- `/terra/` loads three.js from the site itself (`public/terra/vendor/`), not from jsDelivr with no integrity hash (DECISIONS #22).
- Typos fixed on `/software` and in the "Why Blog" post.
- The contact form no longer fails silently when the site is built without
  `PUBLIC_WEB3FORMS_KEY`: the button renders disabled instead of
  posting a request Web3Forms rejects. `./test.sh --live` now fails when production serves the
  form without a key (production does today; the key must be set on the Vercel project), and the
  offline build warns. `DEPLOYMENT.md` documents the variable (DECISIONS #19).
- The Terra demo (`public/terra/index.html`) now honours `prefers-reduced-motion: reduce`: no auto
  orbit, and about four redraws a second instead of one per animation frame. Its browser tests run
  under that setting; on the CI runner's software WebGL the full-rate loop starved the main thread
  and the 375px test timed out (DECISIONS #14).
- `test.sh` started the dev server in the foreground and only passed when an AI agent was the
  parent process (Astro backgrounds on agent detection); in CI it blocked until the 20-minute
  timeout. The server is now started with `astro dev --background` (DECISIONS #12).
- Four "View on Amazon" links on `/reading/` pointed at pages that no longer exist (404); replaced
  with the publisher ISBN product pages. A dead link to a third-party blog was removed from the
  LaTeX test post. The weekly link report had failed every run since 2026-09-27 on these.
- Blog post body styles (`.prose` in `BlogPost.astro`) never reached rendered Markdown, because
  scoped styles do not match `<Content />` output. They are now global, so code blocks scroll,
  images fit and headings scale inside posts.
- Three pages nested a second `<main>` inside the layout's `<main>` (invalid HTML, double gutter).
- Project cards on `/projects/` were wider than a 320–375px screen (the grid's `1fr` min-content
  floor); five pages added a second gutter by reusing `.content-container` inside the layout.
- Contact form inputs were about 269px wide on a 375px phone (four nested paddings); the form now
  gets the full column, the message box has a real height, and the submit button spans the width
  on phones.
- The homepage hid the photo, name, Contact button and LinkedIn/GitHub links entirely under 768px.
  They now stack above the bio.

- Upgraded from Astro 5.15.5 to 7.2.2 via `npx @astrojs/upgrade` and resolved every breaking

- `npm audit fix` to 0 vulnerabilities. Local pre-commit hook rewritten to exact-match filenames.
- Added `test.sh`. Deploy credentials separated from the checked-in templates.
